# 现货条件单（Spot Conditional Orders）— 产品知识

> 来源：产品规格文档《现货条件单(PC、H5、App).pdf》
> 提取日期：2026-07-03
> 覆盖范围：PC / H5 / App 三端

---

## 概述

条件单让交易者预先设定目标价格，只有触达该价格后，限价或市价委托才会被触发。**币币（Spot）和杠杆（Margin）交易均支持条件单。**

关键特性：
- 下条件单时 **不会校验且不会冻结用户可用余额**
- 委托被触发时，如果余额不足，系统自动撤销执行该委托
- 条件单触发前显示在「条件单」列表，触发后转移到「基础单」选项卡

## 参数说明

### 1. 触发后挂限价单
| 字段 | 说明 |
|------|------|
| 触发价 | 最新价达到触发价时，条件单被触发并自动执行一个限价单；触发时余额不足则执行失败 |
| 委托价 | 触发后要执行的限价单的委托价格 |
| 数量 | 触发后要执行的限价单的委托数量 |

### 2. 触发后挂市价买单
| 字段 | 说明 |
|------|------|
| 触发价 | 最新价达到触发价时，条件单被触发并自动执行一个市价单；触发时余额不足则执行失败 |
| 委托价 | 市价单以市场最优价执行 |
| 金额 | 触发后要执行的市价买单的委托金额 |

### 3. 触发后挂市价卖单
| 字段 | 说明 |
|------|------|
| 触发价 | 最新价达到触发价时，条件单被触发并自动执行一个市价单；触发时余额不足则执行失败 |
| 委托价 | 市价单以市场最优价执行 |
| 数量 | 触发后要执行的市价卖单的委托数量 |

## 下单校验（两阶段）

### 阶段 1：下条件单时
- 正常校验：委托价格、委托数量、委托金额
- 市价下单：校验市价单开关是否开启
- **不校验：可用余额**

### 阶段 2：触发后执行时
- 再次校验：委托价格、委托数量、委托金额
- 再次校验：市价单开关
- **新增校验：余额是否充足**
- 任意一项不满足 → 订单执行失败

## 条件单状态机

```
                  ┌── 已取消（待触发→手动/系统/商户/母账号取消）
                  │
待触发 ──────→ 已触发 ──→ 执行失败（余额不足/市价开关关闭/参数校验失败）
                  │
                  └── 已完成（触发后挂单变为终态：完全成交/部分成交撤销/已撤销）
```

### 状态定义

| 状态 | 定义 | 展示位置 |
|:---:|------|:--------:|
| **待触发** | 条件单未触发 | 当前委托列表 |
| **已取消** | 手动取消 / 商户后台取消 / 系统自动取消 / 母账号取消子账号 | 已撤销列表 |
| **已触发** | 条件单已触发，触发后所挂限价单处于当前委托状态 | 当前委托列表（作为基础单） |
| **执行失败** | 触发后执行失败：市价交易关闭 / 余额不足 / 参数校验不满足 | 已撤销列表 |
| **已完成** | 触发后成功执行，所挂委托已变为终态（完全成交/部分成交撤销/已撤销）。显示触发后所挂订单的订单号用于追踪 | 历史委托 |

### 状态变化路径
- 待触发 → 已取消（未触发时取消）
- 待触发 → 已触发 → 已完成（顺利执行）
- 待触发 → 已触发 → 执行失败（触发后执行失败）

## 时间字段

| 时间字段 | 说明 |
|:-------:|:----:|
| **创建时间** | 条件单下单时间 |
| **触发时间** | 条件单触发时间（已取消状态不显示） |
| **更新时间** | 状态变化时间 |

### 不同状态下的更新时间

| 状态 | 更新时间逻辑 |
|:---:|:-----------:|
| 已取消 | 条件单被取消的时间 |
| 执行失败 | 触发后尝试挂单且挂单失败的时间（可能与触发时间完全相同或相差几秒） |
| 已触发 | 等于触发时间 |
| 已完成 | 触发后所挂委托变为完全成交/已撤销等最终状态的时间 |

## 产品启示

1. **两阶段校验设计**：下条件单时不冻结余额（降低用户门槛），触发时再严格校验（防资金风险），是兼顾体验与安全的典型设计
2. **状态机清晰**：5 个状态 + 3 条路径，触发的幂等性和余额校验是关键风控点
3. **与基础单的耦合**：条件单触发后生成的基础单可进一步成交/部分成交/撤销，追踪依赖订单号关联
4. **多端一致性**：PC/H5/App 三端统一逻辑，UI 差异主要体现在条件单列表的交互方式
