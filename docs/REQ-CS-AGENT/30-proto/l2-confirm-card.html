L2 确认卡片 — 交互原型

核心交互场景：用户触发中置信度（50%-79%）请求 → Agent 生成确认卡片 → 用户确认/取消/超时

客服 Agent L2 协作漏斗 核心交互触发点

场景一：用户确认 → 执行成功

U
帮我把每日提现限额从 5 BTC 调到 10 BTC
A
检测到您请求修改提现限额。我已生成操作预览（置信度 72%）：
确认操作
操作：修改每日提现限额 5 BTC → 10 BTC
影响：从今日起每日可提现上限提升至 10 BTC
⚠️ 修改限额为安全敏感操作，请确认
A
✅ 提现限额已修改成功。当前每日上限：10 BTC

场景二：重复点击确认（幂等保护）

同确认卡片连续点击两次确认按钮，第二次返回 "已处理"，不重复执行

A
检测到您请求解锁交易权限。请确认操作：
确认操作
操作：解锁合约交易权限
影响：可进行最高 5x 杠杆的合约交易
⚠️ 高风险操作，请确认
A
✅ 合约交易权限已解锁（第一次操作已成功）
[模拟第二次点击] requestId=abc456 → 后端返回 "already_processed"
幂等保护：同 requestId 5s 内重复请求不执行，业务层保证操作一次且仅一次

场景三：用户取消 → Agent 不执行

U

A

操作：KYC 等级 Lv2 → Lv1
影响：日提现限额从 100 BTC 降至 10 BTC
⚠️ 降级后不可恢复，请谨慎操作
A
❌ 已取消操作。如需进一步帮助，请输入新问题。

场景四：确认超时 → 自动升级 L3 转人工

影响：该 API Key 可发起提现请求
⏰ 倒计时 00:00 — 已超时
A
🔄 未收到确认响应（超时 120s），已为您转接人工客服。

L2 交互要点：① 确认卡片含 requestId 幂等标识 ② 确认后 UI 锁定 ③ 超时后自动升级 L3 ④ 取消操作返回清晰状态
