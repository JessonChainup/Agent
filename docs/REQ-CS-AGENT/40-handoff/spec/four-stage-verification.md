# 人类工程师四阶段验收标准

## 概述

AICoding 交付后，人类工程师按以下四阶段逐层验收。

## 第一阶段：架构评审

**参与角色**：研发架构师 + 产品负责人
**时机**：代码库初始化完成、目录结构和核心接口定义完成后

| 检查项 | 验收标准 | 通过条件 |
|:-------|:---------|:---------|
| 目录结构 | L0 上下文定义的目录结构是否对齐 | 核心目录完整，命名一致 |
| 状态机实现 | 状态机 JSON 中的 7 状态 + 18 迁移是否完整覆盖 | INACTIVE→ACTIVE→...→INACTIVE 全路径可达 |
| 多租户隔离 | tenant_id 是否贯穿所有数据访问层 | 查询/写入/缓存/向量库均隔离 |
| 幂等设计 | requestId 去重是否在确认接口实现 | L2 确认接口支持重复请求去重 |

## 第二阶段：接口验收

**参与角色**：后端开发 + 测试
**时机**：后端 API 开发完成、可部署测试环境后

| 检查项 | 验收标准 |
|:-------|:---------|
| 消息接口 | `POST /instances/{id}/messages` 返回 L1/L2/L3 正确类型 |
| 确认接口 | `POST /instances/{id}/confirm` 同 requestId 第二次返回 `already_processed` |
| 转人工接口 | `POST /instances/{id}/escalation-callback` 正确触发状态回归 |
| 商户配置 | `GET/PUT /merchant/config` 返回正确配置 |
| 审计日志 | `GET /audit/logs` 按 tenant_id 过滤，不跨商户 |
| 离线评测 | `POST /eval/offline` 输出完整评测报告 |
| 身份认证 | 无 Token API 返回 401，FAQ 跳过的认证例外 |
| 限流 | 同一 userId 31 次/分钟请求返回 429 |

## 第三阶段：Code Review

**参与角色**：技术负责人
**时机**：各 L2 任务包 PR 提审后

| 检查项 | 验收标准 |
|:-------|:---------|
| 状态迁移安全 | 非法迁移被拒绝并返回 2001 错误码 |
| 敏感数据处理 | KYC 拒绝原因仅输出预设分类，不输出原始备注 |
| 审计日志不可篡改 | 仅支持 INSERT，不支持 UPDATE/DELETE |
| 缓存隔离 | Redis Key 以 `agent:{tenant_id}:` 为前缀 |
| 幂等一致性 | 同 requestId 的确认请求保证执行一次且仅一次 |
| 错误码一致性 | 所有错误使用 OpenAPI 定义的 ErrorResponse 格式 |

## 第四阶段：集成测试

**参与角色**：测试 + 产品
**时机**：全链路联调完成、预发布环境部署后

| 测试场景 | 验收标准 |
|:---------|:---------|
| 全链路 FAQ | 用户输入 → Agent 自动回复 → 满意度评价 |
| 全链路 L2 | 用户输入 → 确认卡片 → 用户确认 → 执行完成 |
| 全链路 L3 | 用户输入 → 置信度低 → Agent 转人工 → 人工处理完成回调 → Agent 回归 INACTIVE |
| P0 停用 | 模拟准确率暴跌 → 5 个监控周期后自动关闭新请求 |
| 灰度切换 | Phase 1 → Phase 2 → Phase 3 切换正常 |
| 多商户隔离 | 商户 A 和商户 B 数据完全隔离，不可交叉查询 |
| 身份认证 | 未登录用户被拒绝，已登录用户正常查询 |
| KYC 合规 | KYC 查询不返回证件信息，日志自动脱敏 |
