# 004：KYC 合规数据处理

## 目标

实现 KYC 场景的查询处理，遵循数据最小化原则——仅查状态，不查原始材料，自动脱敏，独立 TTL。

## 输入

- 用户 KYC 查询请求（已通过身份认证）
- `GET /api/v1/kyc/{userId}/status` 响应
- `GET /api/v1/kyc/{userId}/levels` 响应

## 输出

- 脱敏后的 KYC 状态回复（不包含原始证件信息）

## 编码范围

```
backend/src/
├── service/
│   └── KYCHandler.ts          // KYC 查询处理
├── infra/
│   └── KycDataMasker.ts       // KYC 数据脱敏和清理
```

## 数据处理规则

- 仅查询字段：status（审核中/通过/拒绝）、level（Lv1/Lv2/Lv3）
- 不查询：证件图片 URL、身份证号、护照号、人脸识别数据
- 拒绝原因仅输出预设分类："证件模糊/信息不一致/证件过期/其他"
- 对话日志中 KYC 相关片段自动替换为"KYC 状态：[已脱敏]"
- KYC 查询结果 30 秒后从运行时上下文中移除
- KYC 相关对话日志保留 ≤ 30 天（独立 TTL）

## 验收标准

| # | AC | 验证方式 | 检查点 |
|:--|:---|:---------|:-------|
| 1 | KYC 状态查询 | AI-VERIFY | 用户查 KYC → 返回状态+等级，不返回证件信息 |
| 2 | 拒绝原因脱敏 | AI-VERIFY | 拒绝原因输出预设分类，不输原始备注 |
| 3 | 日志脱敏 | AI-VERIFY | 对话日志中 KYC 内容→[已脱敏] |
| 4 | 30 秒上下文移除 | AI-VERIFY | KYC 查询结果 30s 后不可在上下文中获取 |
