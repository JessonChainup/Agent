## M3：置信度阈值

### 概述

定义客服 Agent 如何计算、分档、调整每次响应的置信度，驱动三级协作漏斗的决策。

### 置信度分档

| 档位 | 阈值 | 对应漏斗层级 | 含义 |
|:-----|:-----|:------------|:-----|
| 高 | ≥ 80% | L1 全自动 | Agent 有充分依据直接执行 |
| 中 | 50% ~ 79% | L2 确认 | 匹配到候选方案但需客户确认 |
| 低 | < 50% | L3 人工 | 未匹配到可靠方案，转人工 |

### 置信度计算因子

置信度由以下因子加权计算：

| 因子 | 权重 | 说明 |
|:-----|:-----|:------|
| 语义匹配度 | 35% | 用户输入与知识库条目的语义相似度（基于 embedding 余弦相似度）|
| 意图清晰度 | 25% | 用户表述是否存在歧义（同义词比例、否定词、条件表述）|
| 上下文连续性 | 15% | 与会话中前 3 条消息的意图一致性 |
| 操作风险等级 | 15% | 涉及操作的资金影响（0 分：查询；1 分：非资金权限；2 分：资金操作）|
| 历史准确率 | 10% | 同类问题在此商户的历史处理成功/失败比 |

**计算公式**：`置信度 = Σ(因子分值 × 权重)`

每个因子范围为 0~100，各因子权重之和为 100%。

### 商户级阈值微调

商户可在后台配置以下参数，覆盖系统默认值：

| 参数 | 默认值 | 范围 | 说明 |
|:-----|:-------|:-----|:------|
| 全自动阈值 | 80% | 60%~95% | 商户保守/激进的自动化偏好 |
| 确认超时 | 120s | 60s~300s | 客户没响应多久后升级人工 |
| 矛盾升级次数 | 2 次 | 1~5 次 | L2 阶段客户前后矛盾多少次转人工 |
| 高风险操作锁定 | 强制 L3 | 是/否 | 资金操作是否允许 L2 确认执行 |

### 阈值调整策略

- **自动调优**：每周扫描历史处理记录，对某类问题全自动准确率 > 95%（连续 50 次无人工介入修正），自动将该类问题全自动阈值从 80% 下调至 75%
- **人工干预**：商户手动调参数后，记录在变更日志中
- **最大下调**：全自动阈值不得低于 60%（兜底保护）

### 验收标准

**AC-03-01：高分直达**
- Given 用户输入 "我的比特币提现状态是什么"
- When embedding 匹配到 "提现状态查询" 得分 92
- Then 输出置信度 ≥ 80%
- And 进入 L1 全自动处理

**AC-03-02：中分确认**
- Given 用户输入 "帮我把提现限额调高一些"
- When 意图匹配度 65%（存在多个可能的操作路径）
- Then 输出置信度 50%~79%
- And 进入 L2 确认模式

**AC-03-03：低分转人工**
- Given 用户输入 "我的钱不见了"
- When 未匹配到候选方案
- Then 输出置信度 < 50%
- And 进入 L3 转人工

**AC-03-04：操作风险拉低置信度**
- Given 用户请求 "直接提走所有 ETH"
- When 语义匹配度 90%（提现意图）+ 操作风险等级满分
- Then 操作风险因子将置信度拉至 60%
- And 进入 L2 确认模式而非 L1 全自动

**AC-03-05：商户阈值覆盖**
- Given 商户后台将全自动阈值设为 90%
- When 某请求置信度 85%
- Then 按商户阈值而非系统默认值进入 L2

**AC-03-06：自动调优执行**
- Given "ETH 提现状态" 类问题连续 50 次处理正确
- When 商户全自动阈值 80%
- Then 该类问题自动将决策阈值下调至 75%（不低于 60% 兜底）

### 风险

| 风险 | 影响 | 缓解措施 |
|:-----|:------|:---------|
| embedding 模型退化导致语义匹配失效 | 大量 L1 误判为 L3 | 每周评测 embedding 质量，低于基线 10% 触发告警 |
| 商户过度调高全自动阈值 | 风险暴露 | 高操作风险强制锁定 L3，商户不可配置 |
| 自动调优过激进 | 历史 50 次正确但第 51 次出错 | 调优后跟踪 20 次处理，错误率 > 5% 自动回退阈值 |
