## M2：三级协作漏斗

### 概述

将客服请求按复杂度和风险分为三级，逐级兜底。每一级定义触发条件、执行主体、输出约束和升级条件。

### 三级定义

#### L1：全自动——Agent 执行，不通知客户

- **触发条件**：
  - 查询类：FAQ 命中、订单状态、费率查询、币种基本信息
  - 简单操作：已预设规则的账户冻结/解冻、API 权限查询
  - 置信度 ≥ 80%
  - 操作结果在预设安全范围内（不涉及资金变动）
- **执行主体**：Agent 按规则自行执行
- **输出**：直接回复用户结果
- **不允许升级到 L2/L3**：无需人工确认

#### L2：确认——Agent 执行前需客户确认

- **触发条件**：
  - 涉及限额/权限变更：修改提现限额、调整交易权限
  - 涉及客户资产状态变更：冻结/解冻账户
  - 模糊意图：用户表述存在 2 种以上合理解释
  - 置信度 50%~79%
- **执行主体**：Agent 生成操作预览 → 明确列出影响：什么、因为什么、改什么 → 等待客户确认
- **输出**：确认卡片（含操作预览 + 影响范围 + "确认/取消"按钮，带 `requestId` 去重标识）
- **幂等保护**：每张确认卡片携带唯一 `requestId`，后端对 5s 内相同 `requestId` 的确认请求去重，只执行一次操作；确认后卡片 UI 锁定（按钮置灰不可重复点击）
- **WAITING_FOR_CONFIRM 并发消息**：用户在等待确认期间发送新消息，新消息追加为当前确认的上下文，确认卡片保持有效；不退出 WAITING_FOR_CONFIRM 状态
- **升级条件**：若客户连续 2 次确认语义矛盾，升级到 L3

#### L3：人工——转接人工客服

- **触发条件**：
  - 资金异常：提现失败、充值未到账、转错账
  - 疑似欺诈：异常 IP 登录、短时间内多次密码错误
  - 法律/合规：冻结申诉、监管查询
  - 置信度 < 50%
  - 2 次 L2 确认矛盾
  - 客户明确要求转人工
- **执行主体**：人工客服
- **输出**：Agent 整理上下文摘要给人工客服（用户身份 + 会话历史 + Agent 尝试记录）
- **数据传递协议**：
  - 传输通道：HTTPS + TLS 1.3
  - 鉴权方式：Agent → 商户客服系统的 API 调用携带 `agent_signature`（HMAC-SHA256 签名，含 `merchant_id:timestamp:nonce`）
  - 商户侧接收端需提供白名单 IP 或 API Key，Agent 不做主动投递到未配置的第三方系统
- **最小化传递原则**：默认仅传递**问题摘要**（用户意图 + 未解决问题描述 + Agent 已尝试的方案），不传递全量原始对话内容。人工客服需额外请求权限才能获取全量对话历史
- **数据脱敏**：转交的摘要内容自动脱敏——邮箱替换为 `[EMAIL]`、钱包地址替换为 `[ADDRESS]`、手机号替换为 `[PHONE]`
- **转交审计**：每一次 L3 转交记录到审计日志（转交时间、摘要内容 hash、人工客服是否请求了全量历史）
- **回退条件**：人工客服解决后，Agent 继续跟进结案动作

### 升级条件汇总

| 升级方向 | 条件 | 超时 |
|:---------|:-----|:-----|
| L1 → L2 | 置信度低于 80% 且高于 50%，或涉及限额/权限变更 | 30s 内无匹配 |
| L2 → L3 | 置信度降至 50% 以下，或 L2 确认矛盾达 2 次 | 客户 120s 未响应 |
| 任意 → L3 | 涉及资金/安全/合规/法律/人工要求 | 立即 |

### 验收标准

**AC-02-01：L1 直接应答**
- Given 用户提 FAQ 类问题
- When Agent 置信度 ≥ 80%
- Then 直接返回答案，不请求确认
- And 会话记录标记为 L1

**AC-02-02：L2 确认卡片**
- Given 用户请求修改提现限额
- When Agent 置信度在 50%~79%
- Then 输出确认卡片（操作预览 + 影响 + 确认/取消按钮）
- And 等待客户 120s

**AC-02-03：L2 超时升级**
- Given 已发出确认卡片
- When 客户 120s 内未响应
- Then 升级到 L3 人工
- And 随附上下文摘要

**AC-02-04：L2 矛盾升级**
- Given 已发出确认卡片且客户确认
- When 客户在本次会话中连续第 2 次出现语义矛盾
- Then 标记为 L3 并转人工

**AC-02-05：L3 人工转接**
- Given 触发资金/安全/合规条件
- When Agent 判定为 L3
- Then 生成上下文摘要
- And 插入人工客服队列

**AC-02-06：人工解决后回归**
- Given 客户问题已有人工客服处理
- When 客户后续在同一会话中发起新请求
- Then Agent 重新评估级别
- And 从 L1 开始重新计算

### 风险

| 风险 | 影响 | 缓解措施 |
|:----|:-----|:---------|
| L2 确认频繁打断正常流程 | 用户体验差 | 同会话内客户主动拒绝确认超过 3 次→直接升级 L3 |
| L1→L2 误判为简单查询 | 用户被不必要打断 | 历史同类问题正确率低于 85% 的类别，强制 L2 |
| 上下文摘要遗漏关键信息 | 人工客服重复询问 | 摘要模板化 + 强制字段检查 |
