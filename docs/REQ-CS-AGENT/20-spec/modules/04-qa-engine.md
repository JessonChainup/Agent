## M4：AI 问答引擎

### 概述

定义客服 Agent 如何处理不同类别的用户请求，覆盖 FAQ 自助查询、账户管理、充值与提现、KYC 认证、交易操作、Gas 费用六个场景。每个场景定义：输入识别、处理流程、信息源、输出格式、异常处理。

### 场景分类

| 类别 | 典型输入 | 处理模式 |
|:-----|:---------|:---------|
| FAQ | 手续费是多少、怎么充值 | 语义匹配→知识库检索→直接回答 |
| 账户管理 | 我的限额多少、冻结了 | 语义匹配→账户数据 API→状态返回 |
| 充值与提现 | 提现没到账、充值多久确认 | 语义匹配→链上数据查→状态返回 |
| KYC 认证 | 怎么认证、认证没通过、证件过期 | 语义匹配→KYC 状态 API→引导流程 |
| 交易操作 | 怎么买 ETH、订单状态 | 语义匹配→交易 API→详情返回 |
| Gas 费用 | Gas 太高了、网络拥堵 | 语义匹配→Gas 价格数据→建议返回 |

### 通用处理流程

```
用户输入 → 输入安全检测 → 身份认证（涉及个人数据时）→ 分类路由 → 场景匹配 → 参数识别 → 数据获取 → 置信度计算 → 输出
```

各阶段说明：

1. **输入安全检测**：检查敏感词、注入攻击、重复提交（同用户 5s 内相同输入→去重）
2. **身份认证（新增）** ：当查询涉及用户个人数据（账户余额、充提记录、KYC 状态、交易记录）时，必须通过身份认证。认证通过后，本次会话内所有查询不再重复认证（会话级别缓存）。详见下方"终端用户身份认证机制"章节。
3. **分类路由**：基于 embedding 语义匹配分配到 6 大类之一，若全局匹配度 < 30% 则归入"未识别"→转 L3
4. **场景匹配**：在分类内部匹配具体子场景（如"提现没到账"→场景代码 `WITHDRAWAL_STATUS`）
5. **参数识别**：从用户输入中提取参数（币种、交易 ID、数量、地址等）
6. **数据获取**：调用对应内部 API（风控 API/账户 API 等），超时 5s
7. **置信度计算**：按 M3 规则计算
8. **输出**：按场景模板返回

### 场景一：FAQ 查询

- **信息源**：商户自定义知识库（富文本/FAQ 列表/链接文档）
- **内部 API**：知识库搜索接口（embedding 语义检索）
- **输出模板**：

```
{答案文本}

{关联问题 1}
{关联问题 2}
```

- **当知识库无匹配时**：返回"该问题暂未收录，已转人工客服处理"→转 L3

### 场景二：账户管理

- **信息源**：商户后台用户管理 API、充值限额/提现限额配置
- **内部 API**：`GET /api/v1/user/{userId}/status`（账户状态）、`GET /api/v1/user/{userId}/limits`（限额信息）
- **可操作动作**：仅 L2 及以上可执行冻结/解冻/限额调整（写入 API 需商户后台权限校验）
- **输出模板**：

```
您的账户状态：{正常/冻结/锁定}
当前每日提现限额：{金额} {币种}
剩余可用：{金额} {币种}
```

### 场景三：充值与提现

- **信息源**：链上交易数据（区块确认数）、CEX 充提记录 API
- **内部 API**：`GET /api/v1/deposit/{txId}`（充值记录）、`GET /api/v1/withdrawal/{id}`（提现记录）
- **区块确认规则**：各币种最低确认数以 Chainup 配置为准（BTC 1 确认可查询状态，推荐 3 确认；ETH 12 确认）
- **输出模板**：

```
您的{充值/提现}状态：{待确认/确认中/已完成/失败}
交易 ID：{txId}
当前确认数：{current}/{required}
预计完成时间：{估计剩余时间}
```

- **异常处理**：超过 24h 未确认→输出"已超过正常确认时间，建议联系人工客服"→转 L3

### 场景四：KYC 认证

- **信息源**：商户后台 KYC 模块 API、会员等级配置
- **内部 API**：`GET /api/v1/kyc/{userId}/status`（KYC 状态）、`GET /api/v1/kyc/{userId}/levels`（支持的认证等级）
- **KYC 等级映射**：参考 Chainup 标准 Lv1（基础）→ Lv2（进阶）→ Lv3（高级），各等级所需材料不同
- **数据最小化原则**：Agent 仅查询 KYC 状态（审核中/通过/拒绝）和当前等级，不查询用户提交的证件图片、身份证号码、护照号等原始 KYC 材料
- **输出模板**：

```
您的 KYC 认证状态：{未认证/审核中/已通过/被拒绝}
当前等级：{Lv1/Lv2/Lv3}
{已通过时：您的当前验证等级为{等级}，可解锁{功能列表}}
{被拒绝时：拒绝原因：{reason}，请重新提交}
```

- **KYC 拒绝原因脱敏**：拒绝原因模板仅允许输出预设的分类（"证件模糊/信息不一致/证件过期/其他"），不输出人工审核员填写的原始备注文本
- **异常处理**：KYC 审核超过 72h→提供申诉入口
- **KYC 相关内容保留周期**：不超过 30 天，到期自动清理；超期不可回查

#### KYC 数据合规专项要求

| 要求 | 实现方式 |
|:-----|:---------|
| 最小化存储 | Agent 对话日志中 KYC 相关部分自动替换为"KYC 状态：[已脱敏]"，不保留原始原因文本 |
| 不可回查 | KYC 查询结果在返回用户 30 秒后从 Agent 运行时上下文中移除，不持久化 |
| 独立 TTL | KYC 相关对话日志保留 ≤ 30 天，非 KYC 部分保留 180 天 |
| 用户删除权 | 支持按 userId 级联删除所有 KYC 相关日志（含备份数据）|
| 商户可配置 | 商户可在后台自定义 KYC 数据保留周期（7/15/30 天），默认 30 天 |

### 场景五：交易操作

- **信息源**：订单 API、币种信息 API、市场行情 API
- **内部 API**：`GET /api/v1/order/{orderId}`（订单详情）、`GET /api/v1/market/{symbol}`（市场行情）
- **注意区分**：现货/合约/杠杆订单需识别交易类型
- **输出模板**：

```
您的订单状态：{已成交/部分成交/未成交/已取消}
交易对：{symbol}
方向：{买入/卖出}
数量：{amount} {币种}
成交均价：{price} {计价币种}
```

### 场景六：Gas 费用

- **信息源**：公链 Gas 价格 API、Chainup Gas 配置
- **内部 API**：`GET /api/v1/gas/{chain}`（当前 Gas 信息）
- **输出模板**：

```
{网络名称} 当前 Gas：{value} {单位}（{网络状态：拥堵/正常/空闲}）
提现建议：{建议}
- 快速：{high} Gwei（约 {estimateHigh} 分钟到账）
- 标准：{medium} Gwei（约 {estimateMedium} 分钟到账）
- 慢速：{low} Gwei（约 {estimateLow} 分钟到账）
```

- **异常处理**：Gas 价格 API 超时/不可用→返回"当前网络 Gas 数据暂不可用，请稍后再查"

### 终端用户身份认证机制（新增）

#### 背景

当用户通过 Agent 查询个人敏感数据（账户余额、充提记录、KYC 状态、交易记录）时，Agent 必须先验证用户的身份。未通过身份认证的查询请求应拒绝并引导用户先登录。

#### 认证方式

| 方式 | 适用场景 | 实现方案 |
|:-----|:---------|:---------|
| Web 嵌件自动认证 | 用户在交易所 Web 端已登录时 | 前端嵌件读取当前浏览器中交易所的登录 Token（JWT），每请求附带 `Authorization: Bearer <token>` |
| API Token 认证 | 第三方集成/API 调用 | 用户通过商户生成的 API Key + Secret 签名请求，后端验签 |
| 会话内认证（兜底） | 无法从上下文中获取 Token | Agent 发起身份验证流程，引导用户输入邮箱/手机号+验证码或跳转登录页 |
| 批量查询拦截 | 系统监测到异常查询频率 | 同用户每分钟查询超过 30 次自动限流，返回"查询过于频繁，请稍后再试" |

#### 鉴权流程

1. 用户输入到达 Agent，流程进入"身份认证"阶段
2. 检查当前请求是否携带有效 Token
   - 有效且未过期 → 解析 Token 获取 `userId` + `merchantId` → 继续后续流程
   - 无效/过期 → 判断当前场景是否需要个人数据
     - 需要个人数据 → 拒绝处理，返回"请先登录后查询个人账户信息"
     - 不需要个人数据（仅 FAQ）→ 跳过认证，按公开查询处理
3. 认证通过后，本次会话内缓存认证状态（会话级别），同一会话后续请求不再重复认证

#### API 鉴权约束

- 所有涉及用户个人数据的 API 调用必须携带 `userId + merchantId + signature` 后端验签
- `signature = HMAC-SHA256({userId}:{merchantId}:{timestamp}:{nonce})`
- 请求时间戳与服务器时间差超过 60s → 拒绝（防重放攻击）
- 单 `userId` 查询频率 ≤ 30 次/分钟，超限返回"查询过于频繁"并持续 5 分钟冷却

#### 越权查询拦截

- 所有数据查询 API 在返回数据前强制校验：请求中的 `userId` 与 Token 中的 `userId` 一致
- 任何跨用户查询请求 → 拒绝并记录审计日志
- Agent 回复中若涉及另一位用户的资产或 KYC 信息 → 触发 P0 告警

#### AC-04-XX：身份认证相关

**AC-04-09：已登录用户自动认证**
- Given 用户在交易所 Web 端已登录
- When 用户通过嵌件发送"我的余额是多少"
- Then Agent 从请求头中获取有效 JWT Token
- And 解析 Token 获取用户 ID
- And 返回该用户余额

**AC-04-10：未登录用户引导登录**
- Given 用户未在 Web 端登录
- When 用户发送"我的充提记录"
- Then Agent 拒绝处理
- And 返回"请先登录后查询个人账户信息"

**AC-04-11：越权查询拦截**
- Given 用户 A 已通过身份认证（userId = 1001）
- When 用户 A 发送"查一下用户 1002 的余额"
- Then Agent 识别到跨用户查询
- And 拒绝返回数据
- And 记录审计日志（涉嫌越权查询）

**AC-04-12：API 限流保护**
- Given 同一 userId 已在本分钟内发起 30 次查询
- When 该用户发起第 31 次查询
- Then 返回"查询过于频繁，请稍后再试"
- And 持续 5 分钟冷却期

### 多租户隔离架构（新增）

#### 原则

Chainup 是白标 SaaS 平台，不同商户互相独立且为竞争对手。每个商户的 Agent 数据必须严格隔离，任何跨商户数据泄露都属于合规红线事件。

#### 隔离策略

| 维度 | 隔离级别 | 实现方案 |
|:-----|:---------|:---------|
| 知识库 | 独立 Schema 或独立 collection（向量数据库）| 每个商户的知识库 embedding 存放在独立的索引集/collection 中，检索时只搜索本商户索引 |
| 对话日志 | 独立 DB 表或独立 Schema | 商户后台查询对话日志时强制 tenant_id 过滤，API 层后端断言 |
| 商户配置 | 独立配置记录（按 tenant_id 分片）| 配置表的主键包含 tenant_id，查询时强制绑定 |
| 缓存（Redis）| Key 前缀隔离 | 所有缓存 Key 以 `agent:{tenant_id}:{rest}` 格式命名 |
| LLM 上下文 | 运行期隔离 | 单个 Agent 实例的 LLM Context Window 只包含本商户的知识库和配置数据 |
| 评测数据集 | 商户独立标注 | 上线前评测数据集基于商户自有历史客服会话，不跨商户共享 |

#### 向量检索库隔离

- **建议方案**：每个商户使用独立的向量数据库索引集合（Collection），而非全局共享 + tenant_id 过滤
- **原因**：tenant_id 过滤方案在索引碰撞或查询条件遗漏时存在跨商户数据泄露风险
- **备选方案**：若使用同一向量数据库实例，每个商户使用独立的 Collection（如 `faq_{tenant_id}`），检索时指定 Collection 名称
- **重建索引**：知识库更新后的 embedding 重建只影响本商户的 Collection，不影响其他商户

#### 数据访问安全约束

- 所有 Agent 后台 API（商户配置查询、对话日志查看、监控面板）在进入业务逻辑前强制校验：当前登录用户的 `tenant_id` 与请求参数的 `tenant_id` 一致
- 未携带 `tenant_id` 参数的 API 请求默认拒绝
- Agent 后端服务在启动时加载商户白名单列表，非白名单商户的请求直接拒绝（防未授权商户接入）

#### AC-04-XX：多租户隔离相关

**AC-04-13：知识库检索隔离**
- Given 商户 A 和商户 B 的知识库内容不同（A 有 ETH 费率说明，B 无）
- When 商户 A 的用户查询"ETH 费率"
- Then Agent 检索商户 A 的知识库返回结果
- And 不检索商户 B 的知识库

**AC-04-14：对话日志隔离**
- Given 商户 A 的管理员登录后台
- When 查询近 7 天对话日志
- Then 仅返回商户 A 的会话记录
- And 不可包含任何商户 B 的数据

**AC-04-15：Redis 缓存隔离**
- Given 商户 A 和商户 B 的配置不同
- When Agent 读取缓存
- Then 缓存 Key 以 `agent:{tenant_id}:` 为前缀
- And 商户 A 和 B 的缓存数据不冲突

**AC-04-16：未授权商户拦截**
- Given 商户 C 未在 Agent 白名单中
- When 商户 C 的终端用户发送请求到 Agent API
- Then 后端直接拒绝该请求
- And 返回"当前商户未开通智能客服服务"

### 验收标准

**AC-04-01：FAQ 命中**
- Given 用户输入 "现货手续费是多少"
- When 知识库匹配到手续费相关条目
- Then 输出匹配条目的答案
- And 关联问题列表

**AC-04-02：FAQ 未命中**
- Given 用户输入 "你们的旧老板是谁"
- When 知识库无匹配
- Then 返回"该问题暂未收录，已转人工客服处理"
- And 转 L3

**AC-04-03：充值状态查询**
- Given 用户输入 "我的 BTC 充值怎么还没到"
- When 提取到用户身份和币种
- Then 调用链上确认数据 API
- And 输出当前确认数/所需确认数/预计时间

**AC-04-04：KYC 被拒绝引导**
- Given 用户输入 "我认证为什么没通过"
- When KYC 状态为被拒绝
- Then 返回拒绝原因
- And 引导重新提交

**AC-04-05：Gas 查询成功**
- Given 用户输入 "ETH 网络拥堵吗"
- When Gas API 正常响应
- Then 输出当前 Gas + 三档建议 + 预计到账时间

**AC-04-06：Gas API 异常**
- Given 用户输入 "BTC 网络 Gas"
- When Gas API 超时
- Then 输出"当前网络 Gas 数据暂不可用，请稍后再查"
- And 不转 L3（非紧急）

**AC-04-07：输入安全拦截**
- Given 用户输入包含 SQL 注入语句
- When 安全检测触发
- Then 拒绝处理
- And 返回"输入内容不合规，请重新描述"

**AC-04-08：去重保护**
- Given 用户 3s 内连续发送相同的 "我的提现呢"
- When 第二次输入命中 5s 去重窗口
- Then 不重复处理
- And 输出"您的问题已处理中，请稍候"

### 风险

| 风险 | 影响 | 缓解措施 |
|:-----|:------|:---------|
| 知识库匹配到过时信息 | 用户获得错误答案 | 知识库条目增加版本和有效期字段，过期条目不参与语义匹配 |
| 内部 API 因商户定制返回值不同 | 输出模板失效 | 每个场景定义 fallback 输出模板（"该信息暂不可查"），不阻塞流程 |
| 用户输入包含隐私信息（地址/密码） | 日志泄露 | 安全检查层过滤后不保存至日志，仅存"包含敏感类型"标记 |
| 链上数据查询时间长 | 响应超时 | 链上查询设 10s 超时，超时后返回"链上数据查询中，请稍后再试" |

### 基础设施依赖清单（需研发确认）

以下决策项需要研发团队在进入开发前确认技术方案：

| 决策项 | 可选方案 | 建议优先级 |
|:-------|:---------|:----------:|
| embedding 模型选型 | 开源（BGE/Text2Vec/M3E）vs 商业 API（OpenAI Ada）| P0 |
| embedding 部署方式 | 本地 GPU 推理 vs 外部 API 调用 | P0 |
| 向量数据库选型 | Pinecone/Milvus/Weaviate/Qdrant/PostgreSQL pgvector | P0 |
| 知识库增量更新策略 | 全量 reindex vs 增量同步 | P1 |
| 会话上下文持久化 | Redis（临时）vs PostgreSQL（持久）/ 混合方案 | P1 |
| 会话 TTL 配置 | 默认值 30 分钟，商户可配置范围 10~120 分钟 | P1 |
| 上下文窗口上限 | LLM Token 上限（8K/32K/128K），超过后滑动窗口策略 | P1 |
| 全局限流方案 | 商户级 QPS + 用户级冷却期 + LLM API Token 日预算 | P1 |
| 缓存层方案 | Redis 缓存 FAQ embedding 预热结果 + API 数据 TTL 缓存 | P2 |
| LLM 模型选型 | GPT-4o/Claude/DeepSeek/自部署开源模型 | P2 |
